# 编辑器手工功能测试清单

更新日期：2026-10-08。适用于第六批修复、原生关闭保护及内部弹窗统一后的当前源码。先跑通一条完整编辑流程，再分模块检查取消、失败和边界情况；每个结果都要以界面状态和重新读取文件为依据。本清单供后续执行，未填写的项目均为“未测”，不沿用上一轮报告的通过状态。

## 准备测试环境

优先从当前源码启动 Electron，覆盖原生文件选择、磁盘保存、最近项目和文件监听。旧安装程序未必包含当前未提交的修复。

```powershell
Set-Location -LiteralPath 'E:\Projects\Web Projects\puzzle-editor'
npm run electron:dev
```

保持该终端运行。开发版会打开 DevTools；可以收起以扩大编辑区域。此命令使用 3000 端口，若终端显示 Vite 改用了其他端口，应先确认 3000 是否被另一套服务占用，避免测试到旧页面。当前 `electron:start` 仍会访问开发服务器，单独运行它不等于启动生产构建。

准备两个独立测试项目：

1. 将 [已有的有效小型回归工程](./verification/batch6-browser-saved.puzzle.json) **复制到自己选择的测试目录**，得到 `Manual_A.puzzle.json` 和 `Manual_B.puzzle.json`。不要在证据原文件或正式项目上做删除、损坏输入和放弃修改试验。
2. 依次用 `Project → Open Project...` 打开副本，在 `Project → Project Settings...` 将名称改为 `Manual A` / `Manual B`，点击 `Save Changes`。该按钮会保存整个当前项目。
3. 暂时关闭 `Preferences → Auto Save` 并保存偏好，避免自动保存干扰未保存确认测试；记下原值，结束后恢复。普通启动会使用自己的偏好和最近项目列表。
4. 打开 A，执行 `Project → Validate Project`，初始应为 **0 Errors / 0 Warnings**。该夹具已有 Root、Child Stage、Puzzle、Start/End 状态、Go 转移、Imported Graph 和三类作用域变量；`Global Counter` 是 Implemented，可用于删除标记与恢复。

真实 BubbleHorror 示例适合后续兼容测试，但其当前有 7 条既有业务 error，不能用它作为“初始零错误”样本。业务错误也不等同于程序异常。

## 第一轮完整编辑流程

建议先完成下面 10 项。输入完成后按 Enter 或点击字段外部提交；测试全局 Undo/Redo 前把焦点移出输入框。否则 Ctrl+Z 可能只撤销输入框文字。

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| S01 | 打开 A，在 `EDITOR` / `BLACKBOARD` 间切换，点击 Root、Puzzle，再用面包屑或返回按钮返回 | 工作区和 Inspector 对应当前对象；仅导航不产生未保存星号 |
| S02 | Blackboard 的 `Variables → New Variable`，命名 `Test Flag`，类型 boolean，值 false；用名称旁按钮生成 assetName | 名称、类型、值一致；出现未保存星号；新变量 Refs 为 0 |
| S03 | 进入 Puzzle 的 FSM，选中 Go；先将 Comparison 右侧显式选为 False，最后把左侧变量改为 Test Flag | 连线和 Inspector 没有缺失变量提示；Blackboard 卡片与 REFERENCES 都为 1；点击引用能回到该转移 |
| S04 | 在输入框外执行 Ctrl+Z，再执行 Ctrl+Y | 刚才的引用修改被撤销/恢复，Test Flag 计数对应 0 → 1；不把其他对象改成当前对象 |
| S05 | 拖动 FSM 的 Start；再从 `Graphs` 双击 Imported Graph，拖动 Call，并修改 Wait 的 Duration | 节点跟随鼠标、连线跟随端点，松手即停止；选中后 Inspector 值正确 |
| S06 | Ctrl+S，等保存完成；通过菜单重新打开 A | 星号在实际保存成功后消失；变量、条件、节点坐标和 Wait 时长保留 |
| S07 | 在 A 修改一个描述字段；打开 B，文件准备完成后在 `Unsaved Changes` 中选 `Cancel` | 仍在 A，刚才修改仍在，未保存星号保留 |
| S08 | 再打开 B，选择 `Save & Continue`，随后重开 A | 确实进入 B；A 的刚才修改已写入磁盘，重开可见 |
| S09 | 选中 A 的 Implemented `Global Counter`，删除标记后切到 `State: Deleted`，再点 `Restore` | 资源处于待删除时仍存在、属性锁定；恢复后为 Implemented，原值 5 不变 |
| S10 | Validate Project；无 error 时 `Project → Export` 到新的 `.export.json`，再打开导出文件 | 业务定义与绑定保留，Call 的 Temporary Boolean 仍为 false；导入后的项目需要另存为 `.puzzle.json`，不会覆盖运行时源文件 |

S10 的运行时导出会去掉画布坐标等编辑信息；重开导出后自动布局属于既有行为。完整项目保存 S06 才要求坐标保留。导出也不等于保存当前完整工程。

## 第二轮分模块检查

每项先记录前置工程和对象，再操作并填写“通过 / 失败 / 阻塞 / 已知限制”。复杂操作至少再做一次保存重开；不要只看点击当时的界面。

| 编号 | 范围及测试操作 | 通过标准 |
| --- | --- | --- |
| M01 | `New Project` 新建测试工程；名称/位置取消；`Open Recent` 打开副本；打开文件选择器后取消 | 新建文件路径正确；取消不替换当前工程；最近项目指向对应文件 |
| M02 | A 修改后打开 B，分别选 Cancel、Discard、Save & Continue；对新建和 Open Recent 入口也重复 | Cancel 保留 A；Discard 才放弃 A 的未保存修改；Save & Continue 先成功写 A 再切换；三个入口保护一致 |
| M03 | 编辑后保存，再 Undo、Redo；Undo 后再做新修改；输入同值并提交 | Undo 离开保存版本出现星号，Redo 回到保存版本清除；新分支保持未保存，不能 Redo 到旧分支；同值提交不凭空增加历史 |
| M04 | 用文本编辑器另存一个内容为 `{}` 的测试 JSON；在 A 有修改时尝试打开它；再试语法损坏的 JSON | 错误进入 Messages；项目、未保存修改和历史保留，不变成空工程；错误信息指明原因 |
| M05 | 先修改某状态名称并提交，再进入 Project Settings 修改项目描述，点击 Save Changes，重开 | 项目设置和之前尚未保存的状态名称一起保留；不能只保存设置而丢失其他编辑 |
| M06 | Blackboard 四页签切换；搜名称/ID；组合 State / Type 筛选；折叠分组；同组资源拖动排序并 Undo | 显示集合符合筛选；清空筛选后资源恢复；排序和撤销一致；单击详情、Graphs 双击导航到正确图 |
| M07 | 新建并编辑 boolean/integer/float/string 全局变量；值分别用 false、0、0.5、空字符串；在 Stage/Node Inspector 新建局部变量 | 值及类型在保存/重开后保留；局部变量显示正确拥有者，兄弟 Node 的私有变量不应出现在当前节点选择器中 |
| M08 | 在 Stage 概览新建阶段和 PuzzleNode，改名、拖动阶段顺序/层级、展开折叠、单击和双击卡片、返回 | 树、卡片、面包屑和 Inspector 一致；初始子阶段标记跟随层级顺序；不允许把父级拖入自身后代形成循环 |
| M09 | FSM 右键 `Add State`；设置初始状态；单选/追加选择/框选/Escape；单节点和多节点拖动；中键或 Space+左键平移 | 选择集合与高亮一致；移动后的坐标、初始状态可保存；平移只改变视口；松开鼠标后不继续漂移 |
| M10 | FSM 源节点右键 `Create Transition` 后选目标，或 Shift+拖拽；调整端点手柄；选边删除并 Undo；Ctrl+左键划线剪断边 | From/To 正确、吸附点与连线一致；删除/撤销不误伤别的节点或边；连线完成不拖走目标节点 |
| M11 | 演出图添加 Presentation Node、Wait、Branch；绑定 Script/Graph；改起始节点、连接/重新连接节点、改 Wait 时长、设置 Branch 条件和两条分支 | 节点类型及对应 Inspector 正确；脚本/图绑定、startNodeId、nextIds 和分支保存重开不丢；未连接完的 Branch 诊断可解释 |
| M12 | 比较条件、Script 条件与 And/Or/Not 组合；增加、删除、重排子条件；增加常量/变量参数及 Temporary 参数 | 表达式层级、顺序、操作数和绑定目标保持；取消删除不丢内容；false、0、空字符串不被当成“未填写”丢掉 |
| M13 | 新建各类 Script/Event；在 Stage、Node、State 绑定对应 Lifecycle；配置转移 Trigger、Listener 和参数修改器 | 选择器资源类别、作用域正确；配置保存重开保留；Invoke Script 监听器使用当前对象生命周期回调，不要求选择另一段脚本 |
| M14 | 在测试副本中分别删除 Draft、标记删除 Implemented、Restore；待删除资源的永久删除先 Cancel 再确认；随后尝试 Undo | 普通删除按既有历史恢复；Cancel 不删除；永久删除只有确认后发生，旧 Undo 不能复活被永久删除的资源；受影响引用应可诊断 |
| M15 | 使用不同 Stage/Node 声明的同名局部变量建立引用；在黑板查看数量、所属者及点击位置；移除引用并 Undo/Redo | 不串作用域；列表与统计对应；编辑和历史操作后刷新。具体引用范围的已知缺口见后文，不将缺口当成通过 |
| M16 | 给测试工程制造一个未选目标的 Compare，Validate 并点击诊断定位；修复后 Recheck，再 Export | 错误能定位；修复后对应 error 消失；有阻断 error 时不能成功导出；Warnings 与程序异常分别记录 |
| M17 | 调整三栏宽度与 Explorer 上下比例；切视图、保存重开；打开/关闭 Messages，操作一条新消息 | 布局可用、面板不盖住关键操作，已保存尺寸按现有恢复规则生效；消息列表不影响工程内容 |
| M18 | Electron 中开启 Auto Save，间隔设为 1 分钟并保存偏好；在已有文件路径的测试工程中修改，等超过一个周期再从磁盘核对 | 无须手动 Ctrl+S 即落盘；自动保存后没有后续编辑时应 clean。若立刻重开时先被询问保存，不能点保存后再声称自动保存成功 |

| M21 | 比较五类内部弹窗标题、按钮和间距；Tab/Shift+Tab 循环、Escape 取消、点击遮罩；新建时叠加未保存确认后取消；缩小窗口并滚动项目设置/偏好；保存中尝试 Cancel/Escape/Ctrl+Enter | 同一套格式；焦点留在最上层，取消上层保留下层名称草稿；忙碌不能关闭或重复提交；短窗口标题和按钮可见、长内容可滚动。明确取消才能放弃表单草稿 |

单独核对偏好与危险确认外观可启动 `npm run dev`，打开 `http://localhost:3000/tests/fixtures/dialogs-preview.html`。这是独立夹具，偏好 IPC 模拟且仅写内存，不测试真实磁盘或系统选择器；不要把夹具保存成功当成桌面持久化通过。

## 当前能力和专项测试边界

- **独立画布缩放尚未实现**。旧 UX/快捷键文档写有 Ctrl+滚轮，应记“已知未实现”，浏览器页面整体缩放不能记作画布缩放通过。
- **多节点拖动尚无整体撤销**，当前可能需要多次 Undo；将实际行为和期望分别记录，不能把一次 Undo 没有恢复整个组称为本批新问题而不核对基线。
- **原生窗口关闭已接入保存确认**，用 M20 验收。正在打开/新建项目时先完成或取消该操作，再重试关闭。强制杀进程、断电、浏览器标签页关闭和系统强制结束会话不属于本次原生关闭协议的保证范围。
- **Parallel 专用 Inspector 仍不完整**；编辑器负责定义数据，没有游戏运行预览。事件实际触发、脚本执行和演出效果需单独在 Unity 中验证。
- **引用查询存在既有缺口**：演出节点条件中的 ScriptRef，以及转移 invokeEventIds，尚未纳入对应的脚本/事件计数。它们需要补齐查询及删除保护，不能以“卡片数字和详情都相同”认定引用一定完整。
- 只读保护、保存中继续编辑、迟到回调、写入故障、外部文件变更冲突等需要自动测试或受控专项场景。当前未提供面向普通用户的只读切换入口，不要求在界面寻找不存在的开关。
- 安装包还需独立验收。当前源码的 Electron 开发窗口通过，不等于旧安装包或新打包程序也通过。

## 自动检查配合执行

在项目目录另开终端，依次执行，任何一项失败先保留输出并停止将该轮记为通过：

```powershell
npm run check
npm run build
npm run test:electron
```

`check` 包含类型、lint、UTF-8、格式、UI 所属/反向探针和当前自动回归；`build` 验证构建；`test:electron` 使用隔离临时目录做真实文件链路和原生关闭检查，并构建完整生产页面。六类 UI 统一交付时为 226 项回归、原 11 项 Electron 检查及 7 个关闭场景，重跑时以当次实际输出为准。

若要排查大工程卡顿，再单独执行 `npm run bench -- manual-review`。它记录生产模式固定夹具的同步提交等指标，不衡量人工使用时的整窗帧率；避开其他测试进程并行计时。当前构建仍有主 JS 超过 500 kB 的已知警告，成功构建与包体优化是两个验收项。

## 如何记录和判断问题

一条记录只对应一个可重复的问题，推荐格式：

```text
用例编号：S04
环境：当前源码 Electron 开发版 / 浏览器 / 安装包及版本
测试文件：Manual_A.puzzle.json（附能复现的副本）
前置状态：Auto Save 关闭，Test Flag 引用数为 1
操作步骤：点击工具栏移出输入框 → Ctrl+Z → 查看引用数
预期结果：新变量引用数从 1 变为 0
实际结果：填写观察到的变化，不写“好像有问题”
重现次数：例如 3 次中出现 3 次
证据：截图或短录屏、Messages 原文、Console 错误、测试文件
影响：数据丢失 / 保存或导出阻塞 / 编辑错误 / 显示问题
结果：未测 / 通过 / 失败 / 阻塞 / 已知限制
```

找不到入口、工程前置条件不满足或未走到最终保存步骤时记“阻塞”，不要记通过。出现保存成功但重开丢失、取消却切走、不同项目互相覆盖等问题，保留出问题的副本和日志，优先处理，再继续其他模块。

本轮的完成条件是：S01–S10 均有实际结果；需要验收的 M 项逐项记录；未测、失败和已知限制单独列出。若要对某次重构作严格前后比较，还需在保留的旧版本与当前版本中分别使用同一初始夹具，比较业务内容、交互和重开结果，不能只靠“看起来正常”。
