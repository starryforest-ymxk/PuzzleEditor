## 目标与 UX 约束

- 对应 P1-T08/T09、UX §2.1/§3.4/§5/§6：所有内容操作具有一致的撤销、未保存提示和只读保护，查看导航不计入业务历史。

## 1. 集中操作分类

新增 `store/actionPolicy.ts`，使用 `satisfies Record<Action['type'], ActionPolicy>` 检查分类完整性。每项包含领域归属、是否改变内容、历史策略和只读权限。补齐全局 Action 中缺失的 Graph CRUD、边属性及连线方向类型。

切片 Action 类型和类型守卫由分类表中的领域归属派生；顶层 Reducer 统一决定只读拦截及历史，不再分别维护历史和只读名单。Undo/Redo 的保护在最外层生效。

历史策略区分记录、保留、历史边界与按删除状态判定。对资源删除检查实际删除前后的状态：Draft 删除记录历史；非 Draft 资源被物理移除时清空 past/future，防止通过旧快照复活。Implemented 的软删除只改变状态，仍可撤销。所有实际内容变化都推进版本。

外部资源状态同步允许在只读模式执行，作为受控系统更新；仅合并已有字段。发生实际变化时形成历史边界并保守标记 dirty，避免旧快照回滚外部实现状态；无变化不动历史。同步携带会话标识，文件监听还检查路径，拒绝旧会话迟到结果。

## 2. 保存基线与历史快照

EditorState 增加仅内存持有的 `document`：`sessionId`、`revision`、`nextRevision`、`savedRevision`。新会话标识由 Reducer 从上一会话递增，保持更新可重复；新编辑的版本分配独立于 Undo/Redo，不复用分支标识。

历史项使用 `{ content: ProjectContent, revision }`。`ui.isDirty` 由当前版本与保存基线是否相等统一更新；未保存的新项目用 `savedRevision: null`。保留 50 条历史上限。

Undo/Redo 恢复内容及版本，同时保留最新保存时间戳并同步派生脚本清单。导航和选择继续由现有切片负责；历史恢复后通过 `store/historyUi.ts` 保留有效上下文，清除已不存在的选择、导航和多选，不新增路由。

为过滤同值更新和无效删除，使用引用优先的 JSON 数据等价检查：共享分支立即返回，仅比较新建的分支；不做全项目字符串化，不通过与保存文件深比较计算 dirty。项目设置的同值提交不得仅因生成时间戳而产生历史。

## 3. 最小保存确认协议

删除无条件清除 dirty 的 `MARK_CLEAN` 和无会话限制的 `SYNC_UPDATED_AT`，改为 `PROJECT_SAVE_SUCCEEDED`，携带保存开始时的会话、内容版本、目标路径及保存时间。当前项目保存入口在 await 前捕获这些值；只有对应会话/路径的结果可以更新基线。

保存 A 期间继续编辑 B，A 完成后将保存基线设为 A，B 仍 dirty；若 Undo/Redo 回到 A 才 clean。旧会话的保存结果全部忽略，不能覆盖新会话时间戳。保存失败不派发成功确认。

INIT_SUCCESS 同时重置历史和保存基线，可携带 `saved` 标记；新建写盘失败或浏览器中尚未保存时标记为未保存。Header 的 Discard 不再伪造保存成功，替换成功后的 INIT_SUCCESS 自行建立新基线。

浏览器下载和已有新建/打开流程在本批保留其入口形态，统一保存队列与下载确认语义在第二批处理；不将下载触发测试表述为磁盘写入成功。

## 4. 验证设计

使用 Vitest 3.2.7：当前 Node 24 与 Vite 6 满足其依赖范围；参考 [官方 v3 指南](https://v3.vitest.dev/guide/)。先建立捕获现有缺陷的回归，再修实现。

- 状态：Graph CRUD、边属性、同值/无效操作、排序、50 条历史、分支版本、只读编辑和 Undo/Redo、普通导航。
- 生命周期：Draft 删除、Implemented 软删除、MarkedForDelete 永久删除；全局/Stage/Node 变量与脚本/事件。
- 保存：成功、失败、保存中编辑、切换会话后迟到结果、初始化/重置、保存时间戳与内容版本一致性。
- 系统更新：资源状态合并保留用户字段，不清除 dirty，旧会话同步忽略，无变化不清历史。
- 浏览器：新建临时项目，黑板 Graph 创建/编辑/删除及 Undo/Redo、保存后回退、阶段拖拽和相关 UI 提示。
- 检查：前端与 Electron 类型检查、构建、源码 UTF-8、diff 和开发文档链接。

`utils/stageDrag.ts` 编码转换单独处理，严格验证原 GBK 文本与 UTF-8 解码文本一致。

## 实施与验证记录

### 已完成的修改

- `store/actionPolicy.ts` 统一所有 Action 的领域、历史与只读策略，9 个切片的 Action 类型和守卫均由此派生；不再维护多份操作名单。
- `store/documentHistory.ts` 管理会话、编辑版本、保存基线和 50 条历史；普通编辑、Undo/Redo、保存完成均使用同一版本语义。
- `hooks/useProjectActions.ts` 在 await 前捕获保存身份；失败不确认保存，保存期间的新编辑保持 dirty。新建写盘失败和浏览器中尚未保存的新项目也保持 dirty。
- 文件监听校验当前路径，并携带会话标识，拒绝切换后迟到的资源状态同步。Header 的 Discard 不再提前清除 dirty。
- 浏览器验收发现撤销图创建后 Inspector 仍指向已删除图；补充历史恢复后的 UI 校正与对应回归，进入该图画布后再撤销也能退出失效上下文。
- 显式声明 Store 访问 Hook 的返回类型，恢复首批接口的检查能力。由此暴露的 6 处类型错误已定点修正：3 处空选择补 `id: null`、FSM 标题使用所属 Node 名称、2 处消息时间戳使用 ISO 字符串。完整 React 类型和 strict 迁移仍属第四批。
- `utils/stageDrag.ts` 从 GBK 转为 UTF-8；与 Git 基线按原编码解码的文本比较，仅忽略 CRLF/LF 差异，内容完全一致。
- 增加 Vitest 3.2.7、`npm test` 与 `npm run test:run`。锁文件新增 34 个依赖项，既有依赖版本没有变化。
