# CLI 下一阶段开发计划：C6–C10

日期：2026-10-09。当前状态：**C6–C10 已全部完成**。在 C1–C5 离线首版上，本计划逐批补齐删除、转换、覆盖、在线会话和共享历史；当前配套发行及验收见 [C10 完成报告](./CLI_C10_Implementation.md)。C6 实际实现、回归与边界见 [技术设计](./CLI_C6_Design.md)和 [完成报告](./CLI_C6_Implementation.md)；开发测试仅使用虚构夹具，不构成对用户业务工程的高权限操作许可。

## 1. 目标、范围与交付方式

本轮目标：补齐常见工程内容编辑，使外部 Agent 可以删除层级内容、转换兼容文件，并与正在运行的桌面编辑器协作；增加明确授权后的覆盖保存及永久删除能力。

| 纳入下一阶段 | 具体结果 |
| --- | --- |
| 删除 Stage 及子内容 | 按明确子树范围删除 Stage、下属 Puzzle 和其独占 FSM；完整预览关联影响 |
| 删除 Puzzle Node 及关联 FSM | 明确删除对应 Node 和独占 FSM，处理局部资源、引用及编辑器当前选中内容 |
| 兼容格式转换 | 将当前导入器支持的文件转换为完整 `.puzzle.json`，源文件保留 |
| 覆盖保存当前工程 | 用户在 Agent 聊天中明确授权后，按版本前提和文件所有权安全覆盖 |
| 永久删除 Implemented / MarkedForDelete 资源 | 与直接 JSON 编辑同属最高权限，聊天授权后才能执行 |
| 在线编辑 | CLI 显式连接当前桌面会话，读取未保存内容，一次提交完整修改并更新界面 |
| Undo / Redo | CLI 查询并操作当前会话的同一历史栈，防止撤销错误条目和绕过权限 |

暂不增加面板、导航、选中、用户偏好等 UI 操作命令。删除对象后修复失效选择/导航、提交正在输入的字段、显示执行结果属于保证编辑正确所需的内部行为，不是新增对外 UI 控制能力。

MCP、软件内 AI 调用、任意脚本执行、模板/自动布局、Unity 运行时仿真、远程网络服务和跨重启的完整 Undo 历史均不纳入本轮。在线能力首轮验证 Windows x64 桌面版；浏览器继续用于共同领域/UI 回归，离线 CLI 保持独立可用。Undo/Redo 针对打开的会话，离线文件副本不伪装成拥有长期编辑历史。

建议按 **C6 → C7 → C8 → C9 → C10** 顺序实施，每批单独设计、实现、验收和报告，不集中到最后才验证。

## 2. 授权与权限组合

用户已确定：**直接编辑 JSON、覆盖保存当前工程、永久删除已实现或标删资源，三者处于同一最高权限等级，均须用户在 Agent 聊天中明确授权。** 规范唯一维护在 [首版计划新增 §1.3](./CLI_Implementation_Plan.md#13-下一阶段最高权限扩展用户已确认)，本文描述落地设计。

同等级不表示自动互相授权。调用方按用户消息确认项目、任务、动作、文件/实体范围；同一消息可以同时授予多项权限，已有范围内授权持续有效，无需每条命令或每次预览重复确认。

C6 已建立三项独立能力契约，C8 已开放 overwrite；当前三项均可执行：

| 能力 | 拟定声明 | 适用动作 |
| --- | --- | --- |
| `raw_json_write` | 保留 `--allow-raw-json-write` | 直接编写或修改完整 JSON 候选 |
| `overwrite_project` | `--allow-overwrite` | Agent 覆盖已有当前工程，包括在线保存 |
| `permanent_resource_delete` | `--allow-permanent-delete` | 物理移除 Implemented / MarkedForDelete 变量、事件、脚本；包含通过父对象或整文件删除的间接移除 |

这些参数都是调用方对聊天许可的声明，不是软件批准或聊天真实性证明。CLI 不收集聊天记录，不增加审批弹窗或批准令牌；`--yes/--force`、预览回执、客户端自动批准均不能代替用户许可。API 在保留旧权限字段的同时增加机器可读的 requiredCapabilities；新模式的实际输入 Schema、回执版本和错误码在各批设计中固定。

权限按实际动作组合：普通领域删除 Draft 内容并另存，只需普通任务授权；删除父 Stage 内的已实现变量需要 permanent_resource_delete；直接 JSON 候选删除受保护资源并覆盖原文件，需要三项能力。仅有 raw 权限不能借候选实现另外两种高权限效果。

预览可以只读计算实际所需权限和删除清单；缺声明时 apply 在产生副作用前拒绝，返回所缺能力和受影响对象。参数已经表明属于受限操作时尽早拒绝；级联/历史中的受限效果由候选前后比较识别。已有聊天授权不因候选 hash 变化自动失效，但必须重新预览内容并检查仍在授权范围内。

## 3. C6：共同权限策略与层级/资源删除

**已交付**：领域 `stage.delete`、`puzzle.delete`，以及 `variable.purge`、`event.purge`、`script.purge`，累计 47 种 operation；共同能力计算、策略版本回执、历史边界及 GUI/CLI 共用删除均已实现。覆盖能力在 C8 开放实际写入。以下保留验收要求，实现证据见 [C6 报告](./CLI_C6_Implementation.md)。

### 删除规则

1. Stage 根节点不可删除。非空 Stage 删除必须明确选择级联子内容，预览列出全部 Stage、Puzzle、FSM、状态/迁移和局部变量 ID；不能因为名称相同而扩大范围。
2. Puzzle 删除同时移除其独占 FSM。FSM 若仍被删除范围外的 Puzzle 引用，拒绝自动删除并返回所有者；不擅自复制 FSM 或破坏其他节点。
3. 全局事件、脚本、变量和共享演出图不是 Stage/Puzzle 的私有子内容，不随父对象自动删除；失去调用者的图也保留，输出影响说明。
4. 保留既有父子顺序和初始 Stage 规则。删除初始子 Stage 后，新初始项及解锁配置规范化必须进入完整差异；操作 scope 覆盖父级、删除子树和实际受影响兄弟项，不能暗中扩大作用域。
5. 删除范围内的引用随所属内容消失；范围外仍存在的引用必须在同一计划内明确解绑、改接或删除。关联修改要有相应 scope，不能自动清除不相关内容，也不能留下新的悬空引用。
6. Draft 资源沿用普通删除；Implemented 普通 delete 仍为标删；MarkedForDelete 普通 delete 不变成永久删除。专门 purge 可处理用户明确授权的 Implemented 或 MarkedForDelete，不要求 Agent 先伪造状态变化。新建资源仍只能 Draft，不开放任意宣称实现。
7. 删除 Stage/Puzzle 包含受保护局部资源时，同样要求永久删除许可；未授权时保留整批原状。该规则也覆盖 raw 候选及未来在线事务。

### 维护入口与历史

从现有 projectSlice 删除分支抽出纯删除计划/应用逻辑，GUI 与 CLI 共享子树、所有者、引用和最终差异。GUI 保留现有共享 Dialog，不增加 CLI 审批窗口。引用扫描复用 resourceReferences；权限要求由服务端根据操作及前后实体差异计算，不信任调用方自报“没有永久删除”。

C6 已将原先只检查单个 Action 目标的历史判断改为识别实际移除的受保护资源；GUI 中包含永久删除的事务清理可恢复该内容的 past/future，普通层级删除可撤销。在线事务后续须复用同一规则，不能用 Undo/Redo 绕过永久删除。C6 当时的离线候选只输出新文件；C8 已另加明确授权覆盖模式。

**验收**：根保护、深层子树、多个局部 owner 同 ID、初始项变化、共享 FSM、共享图保留、外部引用、末步失败、scope 越界、Draft/Implemented/Marked 三态、级联与 raw 间接删除、无声明零副作用；GUI/CLI 对相同合法删除的内容结果一致。

## 4. C7：兼容格式导入与转换

**已交付**： `import preview` / `import apply`，共用当前 importer 和 serializer。允许当前明确支持的 `puzzle-project`、`puzzle-export`、raw ProjectData、legacy ExportManifest；不扩大为任意 JSON 猜测或未知未来版本兼容。

- 默认转换为新的完整 `.puzzle.json`，不覆盖导出/旧格式源文件；不自动打开或替换当前 GUI 项目。此次转换本身属于普通领域能力；Agent 不能先未经授权手改源 JSON，再通过 import 绕过 raw 权限。
- 返回 detectedFormat、迁移/规范化 notices、诊断、名称缺失清单、完整候选 hash 和转换回执。源没有保存的编辑状态只使用共用默认值并说明，不宣称恢复了已丢失信息。
- 保留源中已有实体 ID、assetName、引用和资源状态。缺失或需修改的 assetName 由调用方通过严格的实体身份→名称映射输入；只接受已识别命名字段，不能变成通用 JSON Patch。未知/重复/遗漏映射拒绝，禁止自动翻译、裁剪或加后缀。已有未改的旧缺名可按错误基线保留并报告；转换实际新增的资产必须有外部名称。
- 当前运行时导入会生成项目 UUID 和时间。为 importer 引入可注入的导入上下文，默认 GUI 行为保持；预览固定新项目 ID、时间、必要迁移/分配及名称映射，提交核对源、映射、转换器版本与候选 hash 后重建同一结果。
- 结构不明或有损迁移拒绝。已有业务 error 可以作为基线保留，转换/显式映射不得新增错误，导出仍要求 error 清零；不提供“一律忽略错误”的开关。
- 复用排他发布、路径/硬链接保护、只读原文与诊断。候选中已有 Implemented 状态属于导入已有声明，不是 CLI 新建声明；不能把导入并入现有工程作为权限绕行。本批只导入为新工程，不做跨工程合并。

**验收已通过**：四类已支持格式、已知旧条件迁移、重复键/数值/编码错误、未知字段/版本、有损旧数据拒绝、显式命名映射、0/false 保持、GUI/CLI 转换等价、预览提交 ID/时间固定、旧回执与已有输出拒绝、源文件原文保持。

C7 新增 59 项回归，累计 31 文件 / 576 项；真实浏览器导入/保存/导出与 CLI 结果一致，独立 Windows 包 55 项检查通过。并修正共用导出器将合法 Wait=0 改为 1 的旧问题。见 [C7 技术设计](./CLI_C7_Design.md)、[完成报告](./CLI_C7_Implementation.md)与 [验收快照](./evidence/CLI_C7/manifest.json)。未知/重复/遗漏映射中的“遗漏”指映射项必要字段缺失，未映射的旧缺名仍按上一条错误基线处理。

## 5. C8：获授权的覆盖保存与工程所有权

**已交付**：领域/raw preview 与 apply 的 in-place 模式、独立覆盖许可、原文备份、持久提交记录与安全重试，以及 Windows 桌面/CLI 路径和文件身份所有权。具体实现和证据见 [C8 设计](./CLI_C8_Design.md)与 [C8 报告](./CLI_C8_Implementation.md)。以下保留验收标准；在线桥仍属 C9。

### 覆盖事务

已实现 `--in-place --allow-overwrite`，与普通 `--out` 模式互斥；只覆盖本次读取的当前工程，不能覆盖任意已存在的第三方目标。import 仍转换为新工程，export 不随此功能获得任意覆盖能力。

overwrite 回执与 create-new 回执严格区分，绑定规范路径、源字节 hash/文件身份、计划或候选指纹、输出预期 hash、操作模式和必要权限。旧的另存回执不能用于覆盖。raw 覆盖同时要求 raw 和 overwrite 声明。

流程：取得本工程独占写入权 → 核对源/候选/回执及磁盘前提 → 保存并核验原字节备份 → 同目录写完整临时文件并校验 → 受控替换 → 重读核验 → 返回结果和备份位置。备份创建失败则不覆盖；不先截断原文件，不自动删除备份。对硬链接、多路径身份无法确认等情况先保守拒绝，不能只比较字符串路径。

覆盖模式增加最小持久提交记录（操作身份、前后 hash、备份、提交阶段），专门用于故障和重试核验，不扩展为通用历史系统。重试遇到目标等于已知输出时返回 already-applied，不把同一计划再次应用到已修改源；目标既非前态也非后态时冲突退出。替换后无法确认必须返回结果不确定及核验信息，不能声称“零写入”。恢复/回滚也要核对当前版本，不能覆盖第三方新修改。

### 所有权与打开的工程

桌面打开/切换/关闭工程和 CLI 写事务共同维护规范路径及文件身份对应的所有权；锁文件/租约的持有者包含进程实例身份，不能只凭旧 PID 猜测可清理。打开新工程失败不放弃旧工程所有权，另存/路径变化按同一顺序转移，文件监听回声与自己写入继续正确过滤。

工程已由兼容桌面会话持有时，离线 in-place 明确拒绝，即使有聊天覆盖许可也不绕过未保存内存；用户/Agent 应显式改用 C9 的 session 操作。无响应、权限或版本不明时不能当作“没有打开”。锁协调只保证遵守协议的客户端，不能承诺阻止所有第三方文件工具；现有旧版桌面程序需升级后才能计入可靠协调范围。

**验收**：缺授权声明、源 hash 变化、多个 CLI 竞争、GUI 持有/切换、备份失败、磁盘写入/替换失败、写后重读失败、进程中断、陈旧登记、同请求重试、第三方修改、输入/输出别名；正确报告 written/already-applied/conflict/uncertain，原文件或已核验备份可追溯。

## 6. C9：在线会话桥与原子编辑（已完成）

实现与验收见 [C9 报告](./CLI_C9_Implementation.md)及 [设计](./CLI_C9_Design.md)。以下保留本批验收要求；实际参数、请求有效期和权限边界以共用契约和使用说明为准。

**交付**：Windows 桌面会话发现、读取当前未保存数据、预览/提交领域计划、显式另存/保存。已有离线命令不静默变成在线，也不在连接失败后退回磁盘写入。

### 通信与目标选择

拟定 `session list/status/inspect/validate/preview/apply/save`。list 返回当前用户可连接实例与工程身份；每次请求明确 instance/session，多个窗口时不猜“最近一个”。此处的会话发现服务于内容编辑，不包含窗口切换和导航命令。

CLI 通过本机 IPC 连接 Electron 主进程，再经受限 preload 契约交给应用层服务及原 Store/ProjectSession。Windows 优先验证 named pipe；Node 提供该 IPC 能力，但当前用户访问边界必须按实际运行时验证，不能把管道名称当作访问控制。[Node 官方 IPC 文档](https://github.com/nodejs/node/blob/main/doc/api/net.md#ipc-support)

主进程核对窗口/主框架、会话身份、协议版本、消息尺寸和请求来源，仅允许注册操作，不开放任意 Action、shell、eval 或文件写入；这与 Electron 对 IPC sender 验证及受限桥接的建议一致。[Electron 官方安全文档](https://www.electronjs.org/docs/latest/tutorial/security#17-validate-the-sender-of-all-ipc-messages)

连接信息使用当前用户受限存储，通信握手只用于防误连/检查传输来源，不证明用户在聊天中授予了编辑权限。C8/C9 开始时先做最小运行时探测与双实例实验；不能验证访问边界时不暴露写接口。首轮不监听远程 TCP、不增加账户登录或聊天上传。

### 在线一致性与提交

在线 token 拟包含 `{instanceId, sessionId, contentEpoch, contentHash}`；工程路径只是附加信息，不能作为会话身份。contentEpoch 在内容编辑、Undo/Redo、外部状态合并及其他会影响快照的变化时单调推进；加载/重置生成新 sessionId。当前 revision 会随 Undo 回退，不能单独当并发前提。

在线只读查询返回 Store 已提交内容，并明确 pendingEdits/当前快照身份；不把字段局部输入草稿声称为已提交项目。preview/apply/save/undo/redo 进入共同编辑屏障：先处理当前字段草稿，再校验 token。草稿提交导致版本变化时返回冲突并要求重读/重预览，不使用 Agent 的旧快照覆盖人工输入。输入无效或用户正在拖动/连接时返回可重试 busy/pending 状态，不强行打断手势。

复用现有隔离候选执行和验证，完整通过后一次提交 project 内容、派生 manifest、诊断和必要 UI 协调；普通批次只有一个 Undo 条目。不能向可见 Store 逐条 dispatch 中间结果，也不能用 INIT_SUCCESS 加载工程来伪装编辑，否则会重置会话/历史。永久删除按 C6 形成历史边界，无变化计划不新增历史或清空 redo。

所有 Agent 与手工内容提交在共同协调器中检查前提；长时间候选计算后提交前再次比对。一次请求包含 requestId 和内容指纹，同会话重复请求返回原结果，同 ID 不同内容拒绝。明确缓存保留边界；进程重启、更换会话或无法确定结果时返回 unknown/expired，不能自动重放修改。请求断开区分尚未提交和已经提交。

### 在线保存与自动保存权限

`session apply` 默认只修改内存，返回 before/after token、changed、dirty、history 信息及 savePolicy。`session save` 通过原 ProjectSession 队列：保存到新路径属于另存；覆盖当前已存在工程须聊天 overwrite 许可及显式声明，同时核对预期磁盘 hash。没有路径时要求明确输出，不唤起 CLI 文件选择器。保存确认只标记实际捕获的版本，之后发生的新编辑继续 dirty。

**必须堵住自动保存绕行**：Agent 未获得覆盖授权的在线 apply/undo/redo，不能借已有自动保存定时器落盘。会话记录这些未获覆盖许可的未保存改动，并在共用保存入口阻止后台自动覆盖，返回清晰原因；不修改用户的自动保存偏好。后续获相应聊天授权并显式保存、另存新文件、或用户本人通过 GUI 保存后再解除对应限制。不能因一次历史授权给未来所有任务永久放行；已排队保存也必须核对其捕获内容是否包含被限制的改动。

人类在 GUI 中主动保存/关闭时的现有交互继续按原规则执行；Agent 不得模拟点击来绕过自己应取得的聊天权限。在线内容提交成功、磁盘保存失败时返回“已编辑、未保存”，保留 dirty 和可重试保存信息，不谎报整个操作没有发生。

首轮在线开放共同领域计划和受控保存；C5 raw 文件入口继续离线使用，遇到打开的工程不得原地绕行。在线整份 JSON 替换不是本轮必需能力，避免顺带新增对 editorState 的界面控制；若以后增加，必须使用同一权限、token、事务和历史政策。

**验收**：读取未保存数据、无窗口/多窗口、连接版本不兼容、关闭/切换工程、readOnly/busy、后台窗口字段草稿、人工输入与多 Agent 竞争、外部资源同步、断线重试、一次事务一次历史、自动保存无许可零覆盖、显式新路径/覆盖保存、失败 dirty 正确；必须操作真实桌面程序验证界面更新。

## 7. C10：CLI Undo/Redo、整体验收与发行

**已交付**：`history list/undo/redo --instance ... --session ...`，以及 CLI + 兼容桌面程序的配套发行。实际契约为 C10 / 22 个入口 / 47 种领域操作 / 在线协议 2；设计与验收分别见 [C10 技术设计](./CLI_C10_Design.md)和 [完成报告](./CLI_C10_Implementation.md)。以下保留本批验收要求。

- 复用当前 Store 的同一 past/future，保留现有 50 条历史上限；不建立 Agent 专用历史栈。为条目增加稳定 entryId、来源、摘要及所需能力元数据，不把这些写进工程领域格式。
- undo/redo 请求带预期 session token、顶部 entryId 和 requestId。只能处理当前可撤销/重做顶部，不能绕过中间人工改动“挑一个旧 AI 操作撤销”。顶部已变化则返回冲突，Agent 先读历史；每次默认一条。
- Undo/Redo 同样递增 contentEpoch，旧 preview 即使内容恰好又相同也不能复用。人类编辑后 redo 清空规则保持；no-op 不消耗历史，断线重试不得撤销两次。
- 权限按实际效果和条目语义判断；Redo 不绕过原操作所需许可，受保护资源永久删除边界不能跨越。普通编辑撤销不一律升为最高权限，内存 Undo 也不代表磁盘回滚。
- Agent 发起的历史变化同样执行 C9 的保存限制：没有覆盖许可时不自动回写；保存后的 Undo 会正确变 dirty。删除对象后的选择/导航由同一历史 UI 协调器修复，不新增导航指令。

发行含新版 CLI、Agent 指引、能力/协议版本、运行时/许可证/哈希，以及带所有权和在线桥的兼容桌面构建；只更新 CLI ZIP 不算在线能力交付。保留 C5 旧包，发布到新目录。Git 提交/推送按用户届时指令执行，不由本计划自动触发。

**整体验收**：

1. 现有 C1–C5 467 项基线继续通过；新增用例数量按实际报告，不预先承诺固定总数。
2. CLI 真实子进程覆盖新命令、权限组合、源/计划/回执冲突、零副作用失败及重试。
3. Electron 真实进程覆盖旧文件会话和关闭保护，加在线读取/编辑/历史/保存/自动保存/双实例；不能仅 mock IPC。
4. 手工执行“打开带未保存修改的工程 → CLI 查询/预览/修改 → 界面核对 → GUI Undo / CLI Redo → 无覆盖声明保存被拒 → 在测试授权范围内覆盖成功 → 重开核对”。
5. GUI 与 CLI 同一合法删除、导入、领域编辑的规范内容/运行时数据相等；失败不会留下半个子树或错误引用。
6. 在仓库外中文空格目录、无全局 Node 环境验独立 CLI；针对实际配套桌面包完成协议、历史与保存冒烟，报告兼容版本及未覆盖平台。
