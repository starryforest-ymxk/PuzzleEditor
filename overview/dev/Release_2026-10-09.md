## 执行设计

1. 核对源和远端：发布前 HEAD 为 `511701b`，与 origin/main 为 0/0；逐项比较 C10 manifest 的 382 份源码和发行产物，均无变化。
2. 复用已完成真实成品回归的 C10 安装器与独立 ZIP；再次编译 Electron，将 22 个运行构建文件与实际 ASAR 和原核验 hash 比较，全部相同。保持仓库既有的 dist-electron 跟踪方式，提交与源码相符的已跟踪编译产物。
3. 发布附件仅包含桌面安装器、独立 CLI ZIP、CLI 入门指南、SHA-256 和发行清单。复制到新 publication 目录并使用无空格的对外附件名，保留原构建目录；不把大二进制放入 Git。
4. 增加 [CLI 入门指南](./CLI_Quick_Start.md)，用真实发行包在隔离练习目录核对创建、领域计划预览/另存、校验和导出例子；只操作虚构工程。
5. 检查暂存区、UTF-8、凭据模式和 git diff --check 后提交推送。核对远端 main，再创建/推送标签；GitHub Release 先建立草稿，上传并核验每个附件的大小与 SHA-256，完成后发布。
6. 发布后查询公开 Release、附件和远端 refs，记录提交/标签/资产信息在忽略目录的 publication manifest；此前 C10 evidence manifest 保留为当批历史快照。

Git 属性将 CLI/Release evidence 按原始字节归档，不转换换行、不清理日志中的原始空白；源码和开发文档继续使用既有格式门禁。这样不会为了提交检查而改写旧候选、回执或证据 hash。
