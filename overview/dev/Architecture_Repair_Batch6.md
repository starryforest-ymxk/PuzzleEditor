## 技术设计

1. **固定夹具**：使用仓库 BubbleHorror 示例（只读）及确定性生成的中型/大型工程；固定 ID、时间、引用分布、节点坐标和随机种子（若需要）。夹具记录 Stage、PuzzleNode、FSM 状态/边、演出节点、全局/局部变量、脚本和事件数，以及序列化文件大小。包含大单图以区分工程总量和当前可见图大小。
2. **测量入口**：新增本地 `bench` 命令，以现有 Vite 构建 React 生产包，在隔离的 Electron/Chromium 中执行。记录首次运行及多次预热后的 p50/p95/max、原始样本、JS 堆与 DOM 数量。算法操作和真实组件 DOM 提交分别计时；同步提交耗时不等同于端到端输入延迟或 FPS。固定 1280×900 视口，关闭后台节流，所有临时文件/用户目录隔离；不接入用户偏好、在线翻译或外部服务。
3. **测量场景**：项目识别/规范化与业务校验、独立校验、完整工程序列化、导出规范化；黑板首次进入、四页签切换、文字筛选、选择和内容更新；FSM/演出图挂载、节点位置提交、Undo/Redo；50 次历史操作后的内存。计数探针核对引用扫描是否重复。
4. **本机交互预算**：本轮以同步筛选/选择提交 p95 ≤ 50 ms、图位置提交 p95 ≤ 16.7 ms、黑板首次进入 ≤ 250 ms、加载/校验/序列化各 ≤ 1 s 为调查阈值，不作为跨设备承诺。首次与预热结果分开；超标必须记录原因或仍待处理，不用调高阈值掩盖问题。
5. **优化决策**：先保存基线数据。若引用扫描占主要开销，按原有遍历语义生成共用计数/索引，避免按每个资源重复扫整工程；用既有查询作为差分对照，覆盖作用域同名 ID、嵌套条件、共享演出图和删除/恢复。若主要成本来自不相关状态更新，再局部收窄订阅/渲染；只有证据支持时才引入缓存或 memo，不全局更换 Store。
6. **兼容与错误处理**：基准构建和测试工具不进入正式应用入口。生产优化不改变校验级别、引用定位及动作历史；缓存只绑定不可变数据身份，不保存跨会话全局单例。基准失败返回非零并保存错误，不能把超时或异常过滤成有效样本。
7. **UI/路由**：沿用现有 Store 导航，无新增路由与产品功能入口。UX §3 的筛选、页签、引用数量/导航，§4/5/6 的下钻、选择/拖动/连线/撤销，§7 的条件与参数，以及项目保存/导出必须保持。独立缩放和多节点整体撤销不混入性能优化。

## 实测与实施结果

### 修改与兼容决策

定位到的主要瓶颈是 Blackboard 引用统计：原 Hook 对每个变量、脚本、事件和演出图分别调用 `find*References`，反复遍历整个工程并构造只在 Inspector 中需要的位置描述。大型夹具引用 Hook 挂载中位数为 275.9 ms，几乎占满黑板挂载和内容编辑时间。

- 新增 `utils/blackboardReferences.ts`：按实体统一统计五类计数。Stage 子树按原查询的 `childrenIds` 建立拥有者关系，局部变量键包含 scopeType/scopeId/id；共享演出图内部引用只遍历一次。
- `useBlackboardData` 保留筛选与统计分离，以不可变 `project` 身份缓存本 Hook 的结果。筛选/选择复用计数；内容编辑、删除标记、Undo/Redo、工程切换重算。没有跨会话全局缓存。
- Inspector 的详细 `find*References` 和导航逻辑保持原样，以它们作为独立差分对照。维持原查询对演出图局部变量的防御性计数；未顺带扩大脚本/事件引用语义。
- 生产代码仅调整该 Hook 并新增统计工具。没有修改 Store 通知方式、画布算法、业务文件格式、保存协议或依赖版本，也没有据包大小告警直接进行拆包或引入虚拟列表。

新增 `tests/performance/` 包含固定夹具、生产组件测量入口、旧 Hook 对照、副本引用查询及正确性回归。旧 Hook 仅在 `--legacy` 基准构建中替换，正式应用入口不引用它。`package.json` 增加 `bench`；格式清单纳入新增文件。

以下数值单位均为 ms；表中“前 → 后”是预热后的 p50。

| 场景 | 示例：前 → 后 | 中型：前 → 后 | 大型：前 → 后 | 大型优化后 p95 |

| Blackboard 挂载 | 1.5 → 1.3 | 23.5 → 4.3 | 302.6 → 17.0 | 23.2 |
| Blackboard 内容编辑 | 0.8 → 0.4 | 20.2 → 1.6 | 276.0 → 6.3 | 7.0 |
| 文字筛选 | 0.6 → 0.9 | 2.4 → 2.6 | 9.9 → 9.3 | 11.5 |
| 页签切换 | 1.0 → 0.9 | 2.9 → 2.8 | 11.2 → 10.6 | 28.0 |
| 选择资源 | 0.3 → 0.3 | 0.7 → 0.7 | 2.5 → 2.3 | 3.4 |

大型 Blackboard 的首次挂载为 **285.0 → 16.8 ms**，消除了本批预设的 250 ms 阈值超标。中型和示例优化后首次为 6.5 / 5.1 ms。筛选/选择 p95 均低于 50 ms，加载/校验/序列化各低于 1 s；在已测规模和上述测量边界内达到预设预算。

画布保持原实现：优化后大型 300 状态 FSM 挂载 p50/p95 为 15.9/17.3 ms，位置提交 2.8/3.9 ms，Undo+Redo 5.6/6.6 ms；160 节点演出图挂载 6.0/8.9 ms，位置提交 1.4/3.2 ms。位置提交低于 16.7 ms 调查阈值。这些画布数值仅作为当前基线，**不把前后波动归因于本次黑板优化**；独立画布缩放尚无实现，未计为性能通过。

强制 GC 后 JS 已用堆，历史从 0 条增长到 50 条：示例 7.612 → 7.628 MiB，中型 9.805 → 9.832 MiB，大型 14.321 → 14.345 MiB。黑板 DOM 元素数分别为 327 / 1,590 / 6,150。此测量只覆盖同一状态连续位置编辑，快照共享结构，**不能推导复杂混合操作的历史内存成本，也不是长期无泄漏证明**。
