# 第二批修复：保存与项目会话流程

> 2026-10-07。状态：第二批完成。承接 [修复计划](./Architecture_Repair_Plan.md) 第二批与 [第一批](./Architecture_Repair_Batch1.md) 的保存版本协议。

## 目标与约束

对应 Task P2-T01/P2-T08/P4-T06、UX §2.1：新建、打开、最近项目、启动恢复、手动保存、自动保存及项目设置使用一致流程；失败和取消保留当前项目、路径、历史与修改。消息与按钮使用 English，说明和关键逻辑注释使用 UTF-8 中文。不改设计原文，不扩展 Unity 或合并工具范围。

## 1. 职责与数据结构

- 每个 StoreProvider 只创建一个 `ProjectSession` 协调器，由 Context 提供给所有入口。纯协调逻辑放在 `services/`，平台适配负责原生对话框、浏览器选择/下载、IPC 和文件 I/O；UI 只发出请求并展示状态。
- Store 保留 Context + Reducer，增加同步的 `getState/dispatch/subscribe` 小接口，用 `useSyncExternalStore` 发布到双 Context。一次 dispatch 只运行一次 Reducer，使“更新设置后立即保存”读取到同一最新版，而不依赖下一次 React 渲染。
- 保存返回判别联合：`saved`（会话/版本/路径/时间）、`cancelled`、`failed`、`downloadInitiated`。队列固定捕获完整 JSON 快照；内部 document 版本不写入文件。
- 运行时只存会话操作的阶段和提示；候选项目、等待中的选择和 Promise 留在协调器内。INIT_SUCCESS 一次提交内容、路径、UI、历史和保存基线，避免分次 dispatch 的中间状态。

## 2. 替换流程

准备候选（选择/读取/解析或构造新项目）→ 检查当前修改 → Save / Discard / Cancel → 等待先前写入 → 最终提交。准备失败不改变当前会话，最近项目与上次路径只在成功提交后更新。

- 保存确认保留 Promise：失败或取消保存选择器时继续显示确认与错误，允许重试或取消。只有 `saved` 且当前会话/版本仍被保存，才能继续；保存期间有新编辑则再次等待选择。
- Discard 只授权替换当前版本，不改变 dirty。浏览器下载仅报告下载已发起，不清除 dirty、不自动继续；按钮明确标记 Download Copy，并保留 Discard/Cancel。
- 新建先在内存构造候选，桌面写盘成功后再提交；写盘失败保留旧项目，新建使用排他创建防止覆盖同名文件。最终提交阶段短暂阻止内容操作，避免候选写入期间漏掉旧项目的新编辑。
- 手动会话请求串行；启动恢复携带启动时的会话及用户操作标识，任何较新的项目请求或编辑都会使迟到恢复失效。启动读取与用户打开不争夺提交权。
- 已知运行时导入不把导出源文件当作项目保存路径；完整导入识别/结构校验仍留第三批。

## 3. 保存、设置与自动保存

- 手动、自动、设置、新建和会话内读取共享 I/O 队列；旧快照不能越过新请求最后写入。保存失败不会阻塞后续请求。旧会话结果不修改当前会话。
- 桌面无路径项目通过 Save Project 原生选择器建立路径，取消不清除 dirty；路径与保存版本在成功确认时一并更新。浏览器保守保留 dirty。
- 项目设置更新内存后保存完整当前项目，移除回读旧磁盘再改 meta 的路径；界面提示保存包含其他未保存修改，失败保留设置与修改以便重试。
- 自动保存只按配置变化建立定时器，每次 tick 读取最新状态，持续编辑不会推迟下一周期；自动与手动保存共用队列。
- 导出继续使用现有校验和归一化，导出成功不确认项目保存。

## 4. Electron 边界与关闭行为

- 读取候选文件必须是纯读取，不提前切换文件监听；增加明确激活已提交项目的 IPC，同步当前监听与最近项目。
- 原生写入使用同目录临时文件和替换，失败尽量保留原文件；新建禁止覆盖。移除监听器按固定时间暂停的盲区，用自身写入内容指纹过滤回声，并清理旧路径的延迟事件。
- 当前主进程关闭/退出未接入未保存确认。本批核对并记录该限制；新增主进程关闭握手协议另列兼容任务，不能把菜单切换保护等同于关闭保护。

## 5. 验证设计

- 保留第一批状态回归，新增协调器与真实 Hook 接线验证：延迟/失败/异常/取消、保存 A 时编辑 B、设置保存完整内容、队列顺序、失败后重试、Save/Discard/Cancel、同路径重开、旧恢复失效、只读与提交阶段保护。
- 假时钟检验持续编辑下自动保存的固定周期；文件监听验证自身写入、真实外部变化和旧路径事件。
- 浏览器实际操作新建、文件选择、下载、取消/放弃/下载后继续，确认提示与 dirty；桌面通过隔离的临时项目验证 Electron 实际文件创建、编辑、写入、重开和失败保护，明确区分 IPC/文件验收与原生 UI 手测。
- 前端/Electron 类型检查、测试、构建、UTF-8、diff 与开发文档链接检查。结果、额外发现及未验证项在完成后补充。

## 实施与验收记录

### 实际修改

1. `services/projectSession.ts` 集中保存、设置保存、新建、打开、最近项目、字符串导入、启动恢复及外部同步；`projectPlatform.ts` 隔离浏览器和 Electron I/O；`projectFiles.ts` 明确序列化字段。
2. `store/editorStore.ts` 同步运行 Reducer，双 Context 继续发布状态/dispatch；每个 Provider 独立持有一个会话协调器，多个 Hook 共用该实例。没有新增状态管理依赖。
3. `INIT_SUCCESS` 原子提交路径、业务数据与 UI，清理旧校验、历史和失效导航；保存确认支持无路径项目首次写入后原子建立路径及基线。
4. Header/ProjectMenu 移除各自的文件读取、提前更新最近项目和固定 100ms 继续逻辑。确认、新建、设置回调保留 Promise 与结果类型；取消不会误报失败，失败时可重试或退出。
5. 浏览器使用 Download Copy，下载保留 dirty；设置下载包含当前全部业务内容。打开完整项目副本后建立该副本的基线。已知运行时导入保持待另存，不覆盖源导出文件。
6. 自动保存按配置建立稳定定时器，tick 读取最新状态；与手动/设置保存共用队列。正在等待用户选择时仍处理原项目的外部资源同步，避免取消后遗漏更新。
7. Electron 新增明确的 `project:activate` IPC；读取候选不切换监听，成功提交后才更新监听及恢复路径。写入采用同目录临时文件替换；新建排他写入，同名失败不覆盖旧文件。
8. 监听器用 SHA-256 内容指纹过滤自身写入，移除固定暂停窗口；路径切换清理延迟事件。真实验收发现 Windows 下 chokidar 斜杠格式与激活路径不同导致同步遗漏，已统一发送激活时的路径身份。
9. 仓库已跟踪的 `dist-electron/` 文件由编译同步更新；测试脚本不写用户项目、偏好或 Chromium 数据。未提交或发布。

### Electron 实际验收

`tests/electron/run-session-smoke.mjs` 启动隐藏的隔离 Electron 窗口，渲染测试页调用真实会话与 preload API，主进程使用实际 IPC 处理器。偏好、Chromium 数据和项目都放入每次新建的 `puzzle-batch2-electron-*` 临时目录，结果写入该目录的 `result.json`；目录由命令输出，可重复运行复查。

已通过：

1. 创建完整临时项目文件。
2. 编辑图后写盘，成功才确认对应版本。
3. 重开实际文件，恢复图内容。
4. 项目设置保存时保留其他尚未保存的图修改。
5. 再次同名新建返回 EEXIST，原会话与磁盘内容均保留。
6. 应用自身写入不触发外部同步回声。
7. 读取其他候选后取消，原项目仍被监听。
8. 外部写入资源状态后正确同步，同时保留本地未保存图修改。

该验收覆盖真实 Electron/IPC/磁盘，不依靠模拟写盘结果；没有手动操作原生打开/保存窗口。原生选择器的取消、异常、路径建立通过平台边界测试覆盖，不将其计为原生 UI 手测。

测试入口最初使用顶层 `await app.whenReady()` 导致 Electron ESM 启动等待；已改为 `app.whenReady().then(...)`，并增加外层超时。该修改仅属于验收工具；Electron ESM 的 ready 时序参考 [官方说明](https://www.electronjs.org/docs/latest/tutorial/esm)。

### 浏览器实际验收

使用独立的 `Batch 2 Verification` 项目，经本地 Vite 页面操作：

- 新建 → Ctrl+S 实际下载：项目仍显示未保存。
- 打开第一批临时项目：先出现保存选择；Download Copy 实际下载，但保留原项目及确认弹窗；Cancel 保留原项目和修改；重新选择后 Discard 才切换。
- 打开下载副本后创建图、修改项目设置并下载：实际 JSON 同时包含新的名称和未保存图；重新打开能看到该图。
- 在有修改时打开损坏 JSON：Messages 出现 English 解析错误，原项目、图和未保存标记仍在。
- 有修改时新建：先填写候选，再确认；Cancel 回到表单且保留旧项目，不显示失败提示；重试并 Discard 后才创建新项目。
- 最终完整重载后的复测以及取消提示修正后的复测，未捕获新增 warn/error。
