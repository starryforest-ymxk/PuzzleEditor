# C8 技术设计：授权覆盖、备份与工程所有权

日期：2026-10-09。状态：设计已实施，验收见 [完成报告](./CLI_C8_Implementation.md)。范围依据 [C8 计划](./CLI_Next_Development_Plan.md#5-c8获授权的覆盖保存与工程所有权)。保留 C3–C7 未提交工作区，不修改用户业务工程；测试仅使用隔离虚构数据。

## 目标和 UX 约束

领域与备用 JSON 的 preview/apply 增加 `--in-place`，apply 另需 `--allow-overwrite`。默认继续新输出；in-place 只覆盖请求源，不能任意覆盖其他已有目标。raw 和永久删除许可独立组合，授权来源仍是用户在 Agent 聊天中的明确消息，不新增软件审批窗或令牌。

对应 UX_Flow §2.1 的打开、保存、校验和 Messages，以及 Project_Overview §3.2 的当前路径保存。桌面原有取消打开、保存失败 dirty、未保存关闭保护、另存、最近项目、监听回声和外部资源状态同步继续成立。取得目标失败时保留原 Store/历史/路径及其所有权；不让 CLI 覆盖尚未保存的桌面内存。C9 在线桥、C10 CLI 历史不在本批。

## 所有权机制与已完成最小探测

在本机 Windows / Node v24.15.0 运行独立双进程 named pipe 探测：首个进程持有时第二个 bind 返回 EADDRINUSE，首个释放后第二个成功。采用 OS 管道句柄持有锁，进程退出由 OS 释放，不写会过期的 PID 锁文件，也不因 PID 不存在、探测无响应而删除他人登记。

`platform/node/projectOwnership.ts` 唯一维护规范路径、文件 dev/ino 身份及进程实例 UUID。分别占用规范路径和已有文件身份的固定摘要管道；持有期间保留替换前后身份，避免重命名或同路径原子替换造成身份空档。拒绝多硬链接文件的覆盖；别名先 realpath 归一化。管道只返回有限的协议/实例/角色元数据，不提供写入、shell 或远程调用。权限不明、协议未知、忙碌均拒绝，不等同于无人持有。

Windows 使用 exclusive 且不开放 readableAll/writableAll。Node 的 [IPC 官方文档](https://github.com/nodejs/node/blob/main/doc/api/net.md#ipc-support)是 API 依据，实际排他性以本机探测和后续真实 Electron 双实例测试验收。C8 的覆盖/所有权保障首轮限定 Windows；其他平台原有另存和 GUI 行为保持，CLI in-place 明确返回未支持。协调只能约束兼容客户端，旧版桌面及任意第三方文件工具仍不受本协议锁约束。

## 覆盖回执与可恢复事务

- 当前入口保持 12 个，领域操作保持 47 个。增加命令模式和可发现 overwrite 回执结构；API 1.0.0、phase/policyVersion C8。C6/C7 旧回执必须重新预览。
- 领域 preview 不带 in-place 时沿用另存契约；apply 必须 out 或 in-place 二选一。raw 两步同样互斥。覆盖回执绑定 mode、规范源路径、字节 hash、dev/ino/时间/大小身份、操作输入、固定时间与候选 hash。原有 create-new 回执不能用于覆盖。
- `platform/node/projectOverwrite.ts` 负责持锁、原文备份、最小持久提交记录、临时文件发布和重试；领域/raw 服务只重建候选、检查权限与输入，不各自实现替换。
- 提交身份由完整回执字节与规范源路径确定。记录和备份位于工程旁的独立事务目录，采用排他创建与明确校验，不覆盖/自动清理旧备份。记录包括请求身份、前后 hash、源身份和提交阶段；备份路径从规范源与提交身份推导，不接受记录内的任意文件路径。
- 顺序：取得路径/身份所有权 → 读取当前文件及已有提交记录 → 验证源和操作输入 → 重建并校验候选 → 保存并重读校验原字节备份 → 持久化提交阶段 → 同目录完整临时写入并 fsync/校验 → 发布前再核对源与其他输入 → rename → 重读候选 hash → 完成记录。
- 同请求若磁盘已为已知后态，使用已验证备份重建原候选并重做权限/输入核验，返回 already-applied；不能再次执行计划。磁盘既非前态也非后态时冲突。中断留下的已知前态可继续；未知、损坏记录或丢失备份保守拒绝。
- 写入前故障保留原文件；替换后的确认/记录失败返回 COMMIT_RESULT_UNCERTAIN 和实际路径、预期 hash、备份/记录信息。不存在“无条件回滚”入口；恢复也必须另行核对当前版本，防止覆盖第三方更新。

## 桌面会话与平台职责

`electron/ipc/projectOwnershipService.ts` 按 webContents 持有活动及候选 lease，并串行化文件相关请求。新增受限 claim/release 调用，claim 成功才允许提交候选；不接受任意 reducer Action 或领域写请求。

`ProjectSession` 保留准备候选与未保存确认顺序，在实际 commit 前申请候选所有权并核对读取时的原文。新建先预留目标再排他写入；另存先取得目标再写，成功后转移活动所有权，失败释放候选且保留旧所有权。后台恢复再次核对 intent/version，取消不转移。旧与新 lease 在切换期间重叠持有，只有成功激活后才释放旧 lease。最近项目/监听更新与所有权切换分开处理，偏好失败不能伪装成取得所有权失败。

主进程写入对活动/候选 lease 复用并刷新文件身份，未激活的临时目标使用短期 lease；导出不能绕过任何已持有工程的保护。窗口实际销毁时释放全部 lease，取消关闭继续持有。浏览器不获得本地文件所有权或覆盖能力，不新增 UI 风格维护点。

## 验收计划

1. 真实 CLI：领域/raw 覆盖成功、保留 UI/原文字节、备份 hash；缺任一能力零写入；out/in-place 互斥、回执模式/源/计划/候选/权限/身份篡改拒绝。
2. 文件故障：备份/临时写/替换/重读/记录失败，前态与后态重试、进程中断、第三方修改、同字节但身份替换、硬链接与别名。
3. 多进程：CLI 竞争、存活但无响应/未知版本所有者、退出/被终止后 OS 释放；不依赖 PID 清理。真实 Electron 持有时 CLI 拒绝，切换失败旧所有权保留，切换成功转移，窗口关闭后可覆盖；双桌面实例不能同时持有同一工程。
4. GUI/Store 回归：打开/新建/另存/自动保存/启动恢复/取消/失败不丢 dirty 与历史；继续跑既有 Electron 会话和关闭场景。浏览器实际打开 CLI 覆盖结果、校验并核对内容。
5. 全量 check、生产构建、独立 C8 CLI ZIP、兼容桌面构建冒烟；更新使用指南、规范、架构、覆盖/状态、报告和独立证据。按实际结果报告，不将已有测试当作本批通过。Git 不自动提交推送。
