# 最近项目子菜单 UI 检查（2026-10-11）

## 检查范围与结论

依据用户提供的菜单截图，对照 `ProjectMenu.tsx`、共享菜单组件、CSS 与 `UI_Standards.md` 检查。本次只记录问题，没有修改产品代码，也没有运行交互回归。

截图可以确认：最近项目子菜单底部出现不必要的横向滚动条；两个项目行的删除按钮越过子菜单右边框，侵入主菜单与子菜单之间的区域。

## 原因

- `components/shared/ui.css` 的 `.ui-menu-item` 同时设置 `width: 100%` 和左右各 12px 的 padding，却没有设置 `box-sizing: border-box`。最近项目行采用 `MenuItem as="div"`，使用默认 content-box，实际行宽超过父容器 24px。当前全局样式没有统一的 border-box 重置。
- `components/Layout/ProjectMenu.tsx` 的子菜单外层设置 `overflowY: auto`，未显式约束横向溢出。此组合会使横向 overflow 计算为 auto，溢出的项目行因此触发横向滚动条。定位桥接用的 padding 与滚动容器混在同一层，也增加边界维护难度。
- 删除按钮在业务组件内定义外观，并通过鼠标事件修改颜色；清空列表分隔线也单独绘制。它们没有完整遵循共享 UI 所有者规范，后续容易与其他菜单样式分化。

## 建议修复范围

1. 在共享菜单项统一使用 border-box，使 button 与 div 菜单项的宽度一致，并检查所有调用方。
2. 将子菜单的定位/鼠标移动桥接与列表滚动区域分开；列表只允许需要的纵向滚动。修正宽度后再限制横向溢出，避免只隐藏越界内容。
3. 将菜单行尾操作按钮收敛到共享菜单组件/CSS，统一悬停、焦点、尺寸和可访问名称；清空列表使用共享分隔线。
4. 验证空列表、长名称、多条记录、删除/清空、鼠标跨菜单移动及键盘操作。

## 验证边界

子菜单目前固定向左打开，源码没有根据视口边界切换方向；窄窗口下是否越界还需实际操作验证。截图顶部是裁切边界，不能据此判断菜单自身被窗口裁掉。本次没有判定项目打开、删除或清空等业务功能失效。

## 修复技术设计（实施前）

本轮目标是修复宽度与滚动，同时收敛按钮、文字和分隔线的维护入口。遵循 UX_Flow 2.1 的项目控制要求；该设计文档未单独规定最近项目子菜单，沿用现有打开、移除最近记录和清空流程，不改变工程数据、路由、保存确认或 IPC。

- 共享 `.ui-menu-item` 使用 border-box 与 min-width: 0，兼容原生 button 和含辅助按钮的 div。其他菜单调用方也使用同一尺寸规则。
- `Menu.tsx` 新增 `MenuScrollArea`，只负责纵向滚动；调用方指定最大高度。项目菜单外层只保留向左定位及鼠标桥接区域，清空动作放在滚动区域之外。
- 新增 `MenuItemText`，集中管理双行名称/日期及长文字截断。新增 `MenuActionButton`，要求可访问名称，统一普通/危险悬停、焦点、禁用态及点击事件隔离；方向键仍交给菜单层。业务组件只提供图标、标签和移除回调。
- 最近记录清空分隔线使用既有 `MenuSeparator`。业务状态仍由 ProjectMenu 的 React state 维护，服务错误处理范围不扩大。
- 验证共享辅助按钮不会触发父行，保留键盘与禁用行为；浏览器检查少量/长名称/多条/空列表、纵向滚动、移除/清空、鼠标桥接及共享菜单调用方。执行完整 npm run check 与生产构建。

## 实施完成与验证结果

上述设计已实现。共享菜单项使用 border-box；最近项目使用 `MenuScrollArea`、`MenuItemText`、`MenuActionButton` 和既有 `MenuSeparator`，移除业务层按钮外观与悬停颜色修改。列表最大高度 240px，清空动作固定在列表之外，定位桥接层不再滚动。菜单项额外拒绝辅助按钮冒泡，覆盖禁用按钮没有自身点击监听器的情况。

`UI_Standards.md` 已登记新增组件的唯一维护入口。静态规则保护按钮与滚动区域的外观，两个新反向探针确认业务层覆盖会被拒绝。
